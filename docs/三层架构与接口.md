# 三层架构与接口约定

本仓库按「表现层 / 业务逻辑层 / 数据访问层」组织，目标是把**动作与指令执行**
做成可测试、可替换、低耦合的一块固件。下文是该约定的唯一权威来源；
新增代码必须遵守，评审时以本文件为准。

## 1. 层次划分

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 表现层 | `user/app/app_command.c`、`app_ui.c` | 串口帧解析与分发、ACK/回包、事件上报；按键、屏幕、蜂鸣、灯 | 直接读引脚/寄存器；直接操作 TIM/SPI/USART |
| 业务逻辑层 | `user/app/app_actuator.c`、`app_power.c` | 状态机、动作序列、参数校验、日志、电源时序 | `#include "pinmap.h"`、`#include "stm32f10x.h"` |
| 数据访问层 | `user/bsp/*.c` + `user/app_port.h` | 唯一接触硬件的地方：GPIO/TIM/SPI/USART/Flash | 包含 `app_*.h`，或做业务判断 |
| 平台层 | `user/main.c`、`user/bsp/bsp_system.c` | 启动顺序、SysTick 时基、看门狗、中断向量 | 业务逻辑 |

依赖方向（只能向下）：

```
app_command.c ─┐
app_ui.c ──────┼─► app_actuator.h / app_power.h ─► app_port.h ◄─ bsp/*.c
               └─► app_types.h / app_config.h
```

`app_port.h` 是分层契约：**业务/表现层只通过它访问硬件**。
要换硬件（比如把步进换成直流电机 + 编码器），只需重写 `bsp/` 与契约，
`app/` 一行不改。

## 2. 接口清单（`user/app_port.h`）

### 系统与时基


## 4. 数据流（一次远程出药）

```
ESP32-C3 --AA55 10 01 03 14--> USART1 ISR --> 环形缓冲
   → Cmd_Tick 组帧 → 校验
   → Act_Dispense(3)  ──► TIM4 PWM 启动（硬件，不占 CPU）
   → ACK(0x10, OK) 立刻回包   ──► USART1
   → ... 2400 个脉冲后 ...
   → Act_Tick 检测完成 → 状态 IDLE、日志、返回码
   → event_poll 发现状态变化 → EVENT(ev=8 MOVE_DONE) ──► USART1
```

## 5. 扩展指引

- 新指令：在 `app_command.h` 定义 CMD，`app_command.c` 的 `dispatch()` 加分支，
  业务动作放 `app_actuator.c`，硬件访问走 `app_port.h`。
- 新传感器：`app_port.h` 加函数声明 → 新建 `bsp/bsp_xxx.c` 实现 → 业务层调用。
- 新显示元素：只改 `app_ui.c`（表现层），不要动 `bsp_lcd.c` 的协议部分。
- 任何一层都不得定义「全局状态变量」给别层直接用，跨层只走函数与 `app_types.h` 结构体。

## 6. 命名与风格

- 文件名：`bsp_<外设>.c`、`app_<职责>.c`；公开函数以模块名前缀（`Motor_`、`Act_`、`Cmd_`）。
- 每个 `.c` 顶部写清：所在层、负责什么、对应原理图哪一页。
- 不引入动态内存；不使用 `printf`（无 stdio 重定向）。
- 中断里只做「搬数据 + 置标志」，逻辑一律在主循环。
