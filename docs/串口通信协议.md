# 串口通信协议

STM32 主控通过三路 USART 与外部模块通信。所有业务数据统一使用下述帧格式，仅命令码与数据段按通道区分。

## 串口分配

| 串口 | 对端模块 | 方向 | 用途 |
|------|----------|------|------|
| USART1 | ESP32-CAM | 双向 | 拍照指令下发 / 识别结果回传 |
| USART2 | HC-08（蓝牙） | 双向 | 服药参数配置下发 / 历史记录读取 |
| USART3 | ESP-01S（WiFi） | 双向 | AT 指令 + MQTT 上报 |

> 具体引脚以 `Core/Inc/pinmap.h` 中硬件成员填写的分配为准。

## 通用帧格式

```
┌───────┬───────┬───────┬───────┬───────────┬──────────┐
│ 帧头1 │ 帧头2 │ 命令  │ 长度  │   数据段   │  校验和   │
│ 0xAA  │ 0x55  │ 1byte │ 1byte │  N bytes   │  1byte    │
└───────┴───────┴───────┴───────┴───────────┴──────────┘
```

- **帧头**：固定 `0xAA 0x55`，用于同步。
- **命令（CMD）**：见下方命令码表。
- **长度（LEN）**：数据段字节数，取值范围 `0 ~ 64`。
- **数据（DATA）**：小端序（多字节整数低位在前）。
- **校验（CHECKSUM）**：从 CMD 到 DATA 末尾所有字节的**异或和**。

## 命令码表（CMD）

| 命令码 | 名称 | 通道 | 说明 |
|--------|------|------|------|
| `0x01` | CMD_TAKE_PHOTO | USART1 | 主控 → ESP32-CAM，请求拍照识别 |
| `0x02` | CMD_PHOTO_RESULT | USART1 | ESP32-CAM → 主控，识别结果回传 |
| `0x10` | CMD_SET_PLAN | USART2 | 手机 → 主控，下发服药计划 |
| `0x11` | CMD_SET_RECHECK | USART2 | 手机 → 主控，下发复检间隔 |
| `0x12` | CMD_GET_LOG | USART2 | 手机 → 主控，请求历史记录 |
| `0x13` | CMD_ACK | USART2 | 主控 → 手机，配置应答 |
| `0x20` | CMD_PUSH_ALARM | USART3 | 主控 → WiFi，漏服告警上报 |

## 关键数据段定义

### 服药计划（CMD_SET_PLAN）

计划支持多组，每组固定 4 字节：

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 0 | 药格编号 | uint8 | 1 ~ N，对应药仓格子 |
| 1 | 小时 | uint8 | 0 ~ 23 |
| 2 | 分钟 | uint8 | 0 ~ 59 |
| 3 | 使能 | uint8 | 1 = 启用，0 = 停用 |

### 识别结果（CMD_PHOTO_RESULT）

数据段 1 字节：

| 值 | 含义 |
|----|------|
| `0x01` | 药片已消失（认为已取药） |
| `0x00` | 药片仍在（未取药） |
| `0xFF` | 识别失败 / 图像异常 |

## 状态码（用于日志与应答）

| 状态码 | 含义 |
|--------|------|
| `0x00` | 已提醒 |
| `0x01` | 药仓已打开 / 已出药 |
| `0x02` | 用户已确认（手动按键） |
| `0x03` | 漏服（复检多次仍未取） |
| `0xFE` | 动作超时 / 异常 |
| `0xFF` | 未知错误 |

> 说明：状态码严格区分“已提醒 / 药仓已打开 / 用户已确认”，**不直接断言“已服药”**，符合产品安全设计原则。

## 异常处理约定

- 接收侧开启超时：单帧接收超过 `100ms` 未完成即丢弃并复位接收状态机。
- 校验失败：丢弃整帧，不产生响应。
- 主控发送指令后未在 `500ms` 内收到应答，视为通信超时并记录日志。
