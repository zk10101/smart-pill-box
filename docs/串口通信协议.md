# 串口通信协议（主控 STM32 ↔ ESP32-C3）

本协议只用于 **USART1**：STM32 主控 ↔ 板载 ESP32-C3-MINI-1 无线模块。
（早期文档里写的 USART2 蓝牙、USART3 WiFi/ESP-01S、ESP32-CAM 拍照，本板**没有**这些电路。）

## 物理层

| 项目 | 值 |
|------|-----|
| 外设 | USART1，115200-8-N-1，无流控 |
| 主控 TX | PA9 → 1k(R33) → ESP32 `RXD0`(pin30) |
| 主控 RX | PA10 ← 1k(R32) ← ESP32 `TXD0`(pin31) |
| 模块使能 | PA8 `NET_EN`（高电平使能，R35 10k 上拉 + C35 100nF） |
| 下载模式 | H3 跳线把 ESP32 `IO9` 拉低后复位（IO9 有 R34 10k 上拉） |

主控端实现：`user/bsp_esp32.c`（接收中断 + 256 字节环形缓冲，主循环 `ESP32_Poll()` 解析）。

## 帧格式

```
┌───────┬───────┬───────┬───────┬───────────┬──────────┐
│ 帧头1 │ 帧头2 │ 命令  │ 长度  │   数据段   │  校验和   │
│ 0xAA  │ 0x55  │ 1byte │ 1byte │  N bytes  │  1byte    │
└───────┴───────┴───────┴───────┴───────────┴──────────┘
```

- **帧头**：固定 `0xAA 0x55`。解析器允许 `AA AA 55` 这种连续帧头（重复的 0xAA 会被跳过）。
- **长度 LEN**：数据段字节数，`0 ~ 128`（`PROTO_MAX_LEN`），超限直接重同步。
- **校验 CHECKSUM**：`(CMD + LEN + DATA[0..LEN-1]) & 0xFF`（**累加和**，不是异或）。
- **多字节字段**：小端序（低位在前）。
- **数据段**：`len == 0` 的帧合法（如心跳）。

示例：

| 帧 | 字节 |
|----|------|
| 心跳 | `AA 55 01 00 01` |
| 查询状态 | `AA 55 02 00 02` |
| 状态应答（IDLE） | `AA 55 80 01 00 81` |
| 检测到已取药 | `AA 55 91 01 05 97` |

## 命令码

| 码 | 名称 | 方向 | 说明 | 主控当前实现 |
|----|------|------|------|--------------|
| `0x01` | `CMD_HEARTBEAT` | ESP32 → 主控 | 保活 | 收到无动作（解析通过即可） |
| `0x02` | `CMD_GET_STATUS` | ESP32 → 主控 | 查询状态 | ✅ 回 `CMD_ACK` + 1 字节状态 |
| `0x10` | `CMD_DISPENSE` | ESP32 → 主控 | 远程手动出药 | ❌ TODO |
| `0x11` | `CMD_STOP` | ESP32 → 主控 | 停止/取消当前流程 | ❌ TODO |
| `0x20` | `CMD_SET_SCHEDULE` | ESP32 → 主控 | 下发服药计划 | ❌ TODO（`SM_SaveSchedule` 已就绪） |
| `0x30` | `CMD_GET_LOG` | ESP32 → 主控 | 读取记录 | ❌ TODO |
| `0x80` | `CMD_ACK` | 主控 → ESP32 | 应答 | ✅ |
| `0x90` | `CMD_SERVER_PUSH` | ESP32 → 主控 | 云端下发（对时/设置） | ❌ TODO（`main.c` 留了分支） |
| `0x91` | `CMD_DETECT_RESULT` | ESP32 → 主控 | 检测结果 | ✅ `STATUS_TAKEN` 触发“已取药” |

## 状态码

| 值 | 名称 | 含义 |
|----|------|------|
| `0x00` | `STATUS_OK` | 正常 |
| `0x01` | `STATUS_BUSY` | 忙（正在出药/提醒） |
| `0x02` | `STATUS_ERROR` | 一般错误 |
| `0x03` | `STATUS_TIMEOUT` | 超时 |
| `0x04` | `STATUS_MISSED` | 漏服 |
| `0x05` | `STATUS_TAKEN` | 已取药 |

主控状态机的状态值（`SM_GetState()`，用于 `CMD_GET_STATUS` 应答）：
`0` IDLE、`1` REMIND、`2` DISPENSE、`3` CHECK、`4` ALARM。

## 建议的数据段定义（待实现）

> 以下为规划格式，主控尚未实现，ESP32 端按此实现时再同步 `main.c`。

### `CMD_SET_SCHEDULE`（0x20）

```
DATA: num(1) + items[num] * { enabled(1), hour(1), minute(1), pill_count(1) }
```

`num ≤ 8`（`SCHEDULE_MAX`），`hour ≤ 23`，`minute ≤ 59`，`pill_count ≥ 1`。
主控校验失败时回 `CMD_ACK` + `STATUS_ERROR`。

### `CMD_DETECT_RESULT`（0x91）

```
DATA: status(1)   // 0x05 = 已取药，其它值主控忽略
```

## 异常与容错

- **校验失败**：静默丢帧，不回错误（避免误帧引发风暴）。
- **长度非法（>128）**：解析器回到等待帧头状态，重新同步。
- **接收溢出**：中断里直接丢弃并累加 `rx_overflow`（`ESP32_GetRxOverflow()` 可查）。
- **帧超时 / 应答超时**：当前主控未实现（解析器是逐字节状态机，无超时）。
  需要可靠应答的场景由 ESP32 侧重发（建议 500ms 超时、3 次重试）。

## 与旧文档的差异（已修正）

旧版本文档描述了三路串口、ESP32-CAM 拍照、异或校验、`0x01 拍照` 等命令，与代码/硬件均不符，已删除：

- 只有 USART1，且对端是 ESP32-C3（无摄像头）；
- 校验是累加和，不是异或；
- `LEN` 上限 128，不是 64；
- 命令码/状态码以 `user/protocol.h` 为准。
