# 串口指令协议（12 格转盘）

STM32F103RCT6 只执行电机动作。ESP32-C3 负责联网与获取摄像头识别出的当前格号；本期 STM32 不触发摄像头，也不判断药是否被取走。

| 链路 | 引脚 | 参数 | 用途 |
|---|---|---|---|
| USART1 | PA9 TX / PA10 RX | 115200-8N1 | ESP32-C3 下发指令、接收结果 |
| USART2 | PA2 TX / PA3 RX | 115200-8N1 | 预留摄像头接口，本期不执行其命令 |

帧：`AA 55 CMD LEN DATA[LEN] SUM`，`SUM = (CMD + LEN + DATA 各字节之和) & 0xFF`。帧间超时 200 ms。多字节运动参数沿用现有协议的高字节在前编码。

## 指令

| CMD | 名称 | DATA | 响应 |
|---|---|---|---|
| `01` | HEARTBEAT | 无 | ACK |
| `02` | GET_STATUS | 无 | STATUS |
| `03` | LINK_PING | `[nonce]` 一字节 | LINK_PONG；仅 USART1 |
| `10` | DISPENSE | 已停用 | ACK PARAM |
| `11` | STOP | 无 | ACK；立即停脉冲，格号失效 |
| `12` | HOME | 已停用 | ACK PARAM |
| `13` | SET_PARAMS | `[steps_hi,steps_lo,speed_hi,speed_lo,flags,00,00]` | ACK；保存到内部 Flash |
| `14` | GET_PARAMS | 无 | PARAMS |
| `15` | CLEAR_ERROR | 无 | ACK；清错后格号仍未知 |
| `16` | PWR_5V | `[0/1]` | ACK；运动中拒绝关闭 |
| `17` | MOVE_SLOT | `[current,target]`，两者均为 1..12 | ACK；仅 USART1 可发 |
| `18` | SYNC_SLOT | `[current]`，1..12 | ACK；视觉重新确认位置，仅 USART1 可发 |
| `19` | NET_STATUS | `[flags]` bit0 Wi-Fi、bit1 MQTT | ACK；仅 USART1 |
| `30` | GET_LOG | `[count]`，最多 20 | LOG |
| `90` | SERVER_PUSH | 已停用 | ACK PARAM；不得解释为云端指令已执行 |

`MOVE_SLOT` 只顺时针走：`delta = (target + 12 - current) % 12`，脉冲数为 `delta * steps_per_slot`。相同格号直接 ACK OK，不发脉冲。若与上次完整运动后保存的预测格号不符，返回 `POS_MISMATCH`；ESP 应重新识别，并用 `SYNC_SLOT` 更新格号，再下发新的 `MOVE_SLOT`。急停或故障后格号失效，下一次动作必须由 ESP 提供识别出的当前格号。没有格号或 `steps_per_slot=0` 时拒绝动作。

`SET_PARAMS` 的 `steps_per_slot` 范围为 1..20000，`speed_hz` 为 100..4000。`flags.bit0` 是 EN 低有效设置，`flags.bit1` 是旋转方向取反。原 `home_backoff` 两字节保留，写入时固定为 0。初次烧录后 `steps_per_slot=0`，必须先在屏幕或指令中标定。参数页 magic 已更新，旧版“每粒步数”不会被误当成格距。

## 回包

| CMD | DATA |
|---|---|
| `80` ACK | `[请求 CMD,状态码]` |
| `82` STATUS | `[state,error,flags,current_slot,累计脉冲(4,低位先),steps_per_slot(2,低位先),speed_hz(2,低位先),target_slot,slot_valid]`，共 14 字节 |
| `83` LOG | `[count,{ev,a,b,t_lo,t_hi}...]` |
| `84` PARAMS | `[steps_lo,steps_hi,speed_lo,speed_hi,flags,00,00]`，沿用原回包顺序 |
| `85` EVENT | `[ev,a,b]`；`ev=8` 表示脉冲发完，`a=预测目标格`，`b=0` |
| `86` LINK_PONG | `[nonce,version,uptime_ms(4,低位先),rx_overflow_low]`，`version=1` |

ACK 状态码：`00 OK`、`01 BUSY`、`02 PARAM`、`03 NOT_HOMED`（旧值）、`04 FAULT`、`05 5V_OFF`、`06 TIMEOUT`、`07 LIMIT`（旧值）、`08 POS_MISMATCH`、`09 NOT_CALIBRATED`。

`STATUS.flags`：bit0 板上 5V、bit1 USB、bit2/3 限位输入、bit4 电机发脉冲中、bit5 预测格号有效。`current_slot=0` 表示未知。`EVENT` 的完成只代表 STEP 脉冲发送完成，不代表电机实际到位；ESP/摄像头后续需复核。

示例：当前 1 格转到 2 格发送 `AA 55 17 02 01 02 1C`；ACK OK 为 `AA 55 80 02 17 00 99`。重新识别为 3 格并同步：`AA 55 18 01 03 1C`。

## 链路诊断

ESP 每 3 秒发送 `LINK_PING`，STM32 原样回显 nonce 和协议版本，并附运行毫秒数及 UART 溢出计数低字节。ESP 必须同时校验帧累加和、nonce、版本，8 秒内收到匹配回包才认定 `stm32_online=true`。STM32 收到有效 PING 后屏幕 `ESP:ON`，10 秒无 PING 显示 `OFF`。ESP 每 3 秒发送 `NET_STATUS`；屏幕分别显示 Wi-Fi 和 MQTT 状态，10 秒没有状态帧则显示 `OFF`。

无动作测试帧：`AA 55 03 01 2A 2E` 表示 nonce=`2A`；若 STM32 运行时间及溢出计数均为 0，返回 `AA 55 86 07 2A 01 00 00 00 00 00 B8`。`NET_STATUS` Wi-Fi 在线但 MQTT 离线为 `AA 55 19 01 01 1B`。这些帧不驱动电机。
