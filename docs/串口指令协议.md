# 串口指令协议（执行机构 ↔ 上位机 / 摄像头）

本协议用于三处：

| 链路 | 物理 | 对端 | 用途 |
|---|---|---|---|
| USART1 | PA9(TX)/PA10(RX)，115200-8N1 | ESP32-C3（NET_TX/NET_RX 交叉经 1k） | 云端指令入口 + 上报 |
| USART2 | PA2(TX)/PA3(RX)，115200-8N1 | MaixBit(K210)，H1 接口 | 触发拍照、回传识别结果 |
| 本地 | 按键/屏幕 | 现场用户 | 不依赖网络 |

两条链路**同一套帧格式**，靠 `CMD` 区分设备；同一帧可被任一链路解析，
实现细节见 `user/app/app_command.c`。

## 1. 帧格式

```
偏移  0     1     2     3     4 .. 3+LEN   4+LEN
    0xAA  0x55  CMD   LEN   DATA[LEN]      SUM
```

- `0xAA 0x55`：帧头。解析器同时容忍 `AA AA 55` 重同步。
- `CMD`：命令码，见下表。
- `LEN`：DATA 字节数，0 ~ 128（`PROTO_MAX_DATA`）。
- `DATA`：参数，多字节整数**小端**（低字节在前）。
- `SUM`：`(CMD + LEN + ΣDATA) & 0xFF`（累加和，**不是**异或）。
  校验失败整帧丢弃并回 `ACK(cmd, ERR_PARAM)` 之外不做任何动作。

帧间超时 200ms（`PROTO_FRAME_TIMEOUT_MS`），超时未收全则丢弃当前帧重新找帧头。

## 2. 指令表（上位机 → 执行机构）

| CMD | 名称 | DATA | 说明 |
|---|---|---|---|
| `0x01` | HEARTBEAT | 无 | 保活；回 ACK |
| `0x02` | GET_STATUS | 无 | 回 `0x82 STATUS` |
| `0x10` | DISPENSE | `[粒数]` 1~10 | 出药；需已回零，否则 `ERR_NOT_HOMED` |
| `0x11` | STOP | 无 | 急停：停脉冲、失能、回 IDLE（位置失准） |
| `0x12` | HOME | 无 | 回零：反向找 PC6 → 正退 backoff → 位置清零 |
| `0x13` | SET_PARAMS | `[sppH,sppL,spdH,spdL,flags,backoffH,backoffL]` | 写参数并保存 Flash |
| `0x14` | GET_PARAMS | 无 | 回 `0x84 PARAMS` |
| `0x15` | CLEAR_ERROR | 无 | 清故障、关报警 |
| `0x16` | PWR_5V | `[0/1]` | 关/开 5V（IP5306 KEY 软开关） |
| `0x30` | GET_LOG | `[条数]` 1~20 | 回 `0x83 LOG`（最新在前） |
| `0x40` | CAM_TRIGGER | 无 | 通知 K210 拍照（USART2 转发同一帧） |

`SET_PARAMS.flags`：bit0 = `en_active_low`，bit1 = `dir_invert`。
`spp` 每粒步数 100~5000；`spd` 脉冲频率 100~4000Hz；`backoff` 回零后退出步数 0~500。

## 3. 回包（执行机构 → 上位机）

| CMD | 名称 | DATA | 说明 |
|---|---|---|---|
| `0x80` | ACK | `[cmd, status]` | 每条指令都回；`status` 见下表 |
| `0x82` | STATUS | `[state, error, flags, pills, pos(4), spp(2), spd(2)]` | 当前状态快照 |
| `0x83` | LOG | `[count, {ev,a,b,t(2)} × count]` | 环形日志，最新在前，`t` 为毫秒低 16 位 |
| `0x84` | PARAMS | `[spp(2), spd(2), flags, backoff(2)]` | 当前参数 |
| `0x85` | EVENT | `[ev, a, b]` | 状态迁移/故障主动上报（约 50ms 内） |
| `0x41` | CAM_RESULT | `[found, count, conf]` | K210 识别结果（USART2 收到后转报 USART1） |
| `0x90` | SERVER_PUSH | 由云端定义 | 本固件只解析不使用，预留给服务器下发 |

### ACK 状态码

| 值 | 名称 | 含义 |
|---|---|---|
| `0x00` | OK | 已受理/已执行 |
| `0x01` | BUSY | 电机正忙，拒绝新动作 |
| `0x02` | PARAM | 参数非法 |
| `0x03` | NOT_HOMED | 未回零，不能出药 |
| `0x04` | FAULT | 驱动器 FAULT 或处于故障态 |
| `0x05` | 5V_OFF | 5V 不在位（电机/驱动无电） |
| `0x06` | TIMEOUT | 动作超时 |
| `0x07` | LIMIT | 顶到终点限位被止损 |

### state / error / ev 取值

- `state`：0=IDLE，1=HOMING，2=MOVING，3=ERROR（与 `ActState` 一致）
- `error`：0=NONE，1=FAULT，2=TIMEOUT，3=NOT_HOMED，4=NO_LIMIT，5=5V_OFF，6=BUSY，7=PARAM，8=LIMIT_STOP
- `ev`（EVENT）：1=POWER_ON，2=5V_ON，3=5V_OFF，4=HOME_START，5=HOME_DONE，6=HOME_FAIL，
  7=MOVE_START，8=MOVE_DONE，9=MOVE_ABORT，10=FAULT，11=TIMEOUT，12=CMD_DISPENSE，
  13=CMD_STOP，14=CMD_HOME，15=KEY，16=CAM_RESULT，17=PARAM_SAVED

## 4. 示例帧

| 场景 | 字节 |
|---|---|
| 查询状态 | `AA 55 02 00 02` |
| 出药 3 粒 | `AA 55 10 01 03 14` |
| 出药 3 粒的 ACK(OK) | `AA 55 80 02 10 00 92` |
| 回零 | `AA 55 12 00 12` |
| 心跳 | `AA 55 01 00 01` |
| 心跳 ACK | `AA 55 80 02 01 00 83` |

## 5. 摄像头（K210）交互

- 执行机构在收到 `0x40 CAM_TRIGGER` 后，通过 USART2 原样转发该帧；
  K210 收到后拍照+识别，回 `0x41 [found,count,conf]`。
- 执行机构把结果转报 USART1（`0x85 EVENT`，`ev=16`），并记入日志。
- 电气注意：H1 的 5V_SW 由 SW3 手动切换，MCU 无法给摄像头软上电；
  另外 H1 的 UART 与 MCU 之间各串 1k，K210 侧电平为 3.3V，可直连。
