# 主控状态机设计（与 `user/state_machine.c` 一致）

主控固件的核心是五态状态机。实现文件 `user/state_machine.c`，状态枚举在 `user/state_machine.h`。

本文件描述**当前代码的真实行为**（不是设计愿景）。未实现的部分统一列在文末 TODO。

## 状态定义

| 状态 | 枚举 | 说明 |
|------|------|------|
| IDLE | `SM_IDLE` | 待机：每到新的一分钟判断一次服药计划 |
| REMIND | `SM_REMIND` | 提醒：蜂鸣 + 红灯，等待用户按键确认 |
| DISPENSE | `SM_DISPENSE` | 出药：TIM4 发 STEP 脉冲，限位/故障/超时结束 |
| CHECK | `SM_CHECK` | 等待取药：超时催促，可用 ESP32 检测结果提前结束 |
| ALARM | `SM_ALARM` | 告警：持续报警音，等用户确认 |

## 状态流转

```
                 ┌────────── 每分钟匹配服药计划 ──────────┐
                 ▼                                        │
IDLE ──时间到──► REMIND ──按 OK──► DISPENSE ──到位──► CHECK ──按 OK/检测已取──► IDLE
  ▲                │                    │                │
  │                │重试 3 轮仍未确认     │FAULT/超时        │催促 3 次仍未取
  │                ▼                    ▼                ▼
  └────────── ◄── ALARM ◄───────────────────────────────┘
                 （按 OK 确认后回 IDLE）
```

## 转换表（对应代码位置）

| 当前状态 | 条件 / 事件 | 下一状态 | 实际动作 |
|----------|-------------|----------|----------|
| IDLE | 当前“时:分”命中某条启用的计划，且该分钟未被判断过 | REMIND | `Buzzer_Beep(1000)`、红灯 |
| REMIND | 按 `KEY_OK`（短按） | DISPENSE | `Motor_Dispense(pill_count * MOTOR_STEPS_PER_PILL)` |
| REMIND | 每 `REMIND_RETRY_S`（120s）处理一次，共 `REMIND_BEEP_TIMES`（3）次机会 | REMIND / ALARM | 第 1、2 次再响一轮，第 3 次转 ALARM |
| REMIND | 按 `KEY_DN` / 长按 `KEY_BACK` | REMIND | 仅静音，状态不变 |
| DISPENSE | `Motor_GetStatus()==MOTOR_DONE` | CHECK | 蓝灯，等待取药 |
| DISPENSE | `MOTOR_FAULT` / `MOTOR_TIMEOUT` | ALARM | 立即告警 |
| CHECK | 按 `KEY_OK`，或 ESP32 回 `CMD_DETECT_RESULT` + `STATUS_TAKEN` | IDLE | 灭灯、停响 |
| CHECK | 每 `RECHECK_INTERVAL_S`（60s）处理一次，共 `RECHECK_MAX_TIMES`（3）次机会 | CHECK / ALARM | 第 1、2 次短响 + 红灯催促，第 3 次判漏服转 ALARM |
| ALARM | 按 `KEY_OK` | IDLE | 停响、灭灯（日志/上报告警：TODO） |
| 任意 | 主循环停止喂狗 >4s | 复位 | IWDG 复位（`main.c` 每轮循环 `IWDG_ReloadCounter()`） |

## 关键实现细节

### 时间基准

- `SM_Tick()` 在 `SysTick_Handler` 中每 1ms 调用一次，内部维护 `sm_ms`；
- 所有阶段计时（`phase_ms`）都基于 `sm_ms`，主循环不阻塞；
- 软件时钟在 `main.c` 里每 1000ms 进位一次（原实现每 10ms 加 1 秒，已修复）。

### 同一分钟不重复触发

`last_minute_key = hour*60 + minute`：每分钟只判断一次。用户确认取药回到 IDLE 后，
同一分钟内不会再次触发同一条计划；到下一分钟才重新判断。

### 出药

- 步数 = `pill_count * MOTOR_STEPS_PER_PILL`（默认 800 步/粒，需按机构标定）；
- STEP 由 `TIM4_CH3`(PB8) 输出，800Hz（`MOTOR_STEP_FREQ_HZ`）；
- `Motor_Tick()` 每 1ms 检查：`FAULT_N`(PC13) 低 → 故障；`LIM_POS`(PC7) 低 → 到位；
  超过 `MOTOR_TIMEOUT_MS`(5000ms) → 超时；
- 驱动器使能：`EN` = **PC12**（原理图 A3→B3=EN），极性见 `MOTOR_EN_ACTIVE_LOW`。

### 复检（无摄像头时的降级策略）

板上只有 ESP32-C3（无摄像头、仓库里也没有 ESP32 固件），所以：

- 主控先按“催促 + 超时”工作：蓝灯提示 → 每 60s 短响催促 → 3 次后判漏服；
- 若 ESP32 侧将来接入检测手段，向上发 `CMD_DETECT_RESULT` + `STATUS_TAKEN`，
  主控收到后立即结束 CHECK，比本地计时更准（`SM_OnPillTaken()`）。

### 持久化

- 服药计划存内部 Flash 最后一页（`0x0803F800`，magic `0x50425831`），见 `bsp_storage.c`；
- 首次上电无有效数据时写入默认计划：08:00、19:30 各 1 粒；
- 外部 W25Q64 因 `FLASH_CS` 未接 MCU 而禁用（`FEATURE_EXT_FLASH=0`）。

## 蜂鸣器/彩灯约定

| 场景 | 表现 |
|------|------|
| 提醒（首轮/重试） | 响 1000ms，红灯 |
| 出药 | 红灯保持 |
| 等待取药 | 蓝灯 |
| 催促取药 | 短响 300ms + 红灯 |
| 告警 | 连续 3 短 2 长循环（`Buzzer_Alarm`），红灯 |
