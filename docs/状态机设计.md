# 主控状态机设计

主控固件的核心是五态状态机，运行于 `main.c` 的主循环中，由 `state_machine.c` 实现。

## 状态定义

| 状态 | 枚举值 | 说明 |
|------|--------|------|
| IDLE | `SM_IDLE` | 待机：读 RTC、刷新 OLED、匹配服药计划 |
| REMIND | `SM_REMIND` | 提醒：蜂鸣初鸣 + OLED 提示 |
| DISPENSE | `SM_DISPENSE` | 出药：驱动步进电机推送，限位触发或超时停止 |
| CHECK | `SM_CHECK` | 拍照检测：向 ESP32-CAM 发指令并等待识别结果 |
| ALARM | `SM_ALARM` | 告警：本地二次报警 + 云端推送 |

## 状态流转

```
IDLE ──(时间到)──► REMIND ──► DISPENSE ──► CHECK
                                             │
                    ┌──────────药片消失？────┤
                    │ 否                      │ 是
                    ▼                         ▼
              复检 / ALARM              记录成功，回 IDLE
                    │
                    └──────────► IDLE
```

## 转换表

| 当前状态 | 事件 / 条件 | 下一状态 | 动作 |
|----------|-------------|----------|------|
| IDLE | RTC 时间命中服药计划 | REMIND | 蜂鸣初鸣，OLED 显示提示 |
| REMIND | 开始出药 | DISPENSE | 启动步进电机 |
| DISPENSE | 限位触发 / 超时 | CHECK | 停电机，向 ESP32-CAM 发拍照指令 |
| CHECK | 识别结果 = 药片消失 | IDLE | 记录“已取药”日志 |
| CHECK | 识别结果 = 药片仍在，未达复检上限 | CHECK | 等待复检间隔后再次拍照 |
| CHECK | 复检次数达到上限（仍未取） | ALARM | 本地蜂鸣 + OLED 警告 + 云端上报 |
| ALARM | 用户按静音键 | IDLE | 消音，保留告警标记继续上报 |
| 任意 | 动作超时 / 传感器异常 | ALARM | 停止执行器，记录异常日志 |

## 关键约束

- **超时保护**：出药、拍照等待均设超时，超时即停止执行器并转 ALARM，禁止重复驱动。
- **复检机制**：按配置间隔循环拍照，达到 `MAX_RECHECK` 次仍未取药才判定漏服。
- **安全边界**：状态只记录“已提醒 / 已出药 / 已确认”，不推断“已服药”。
- **看门狗**：主循环喂狗，防止程序跑飞。
